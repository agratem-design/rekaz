# ركاز v2 — وثيقة المواصفات

> المرجع الملزم لإعادة بناء المنظومة من الصفر في مجلد جديد (`E:\ركاز-v2`).
> المجلد الحالي `E:\ركاز` يبقى للقراءة فقط، ولا يُنسخ منه كود أو واجهات أو ترحيلات. نأخذ منه **ماذا يفعل النظام** فقط.

> الحالة: **مسودة للمراجعة**. كل ما هو مكتوب هنا قابل للتعديل قبل البدء بالكود. الأسئلة المفتوحة في القسم 9.

## 1. ما هو النظام

منظومة إدارة لشركة مقاولات وتشطيبات (العملة: الدينار الليبي د.ل)، تدير:

- **المشاريع** بنوعين مختلفين محاسبياً:
  - **مقاولات (سعر ثابت):** قيمة المشروع = العقد أو مجموع بنود المقايسة. الربح = القيمة − التكاليف المباشرة.
  - **تشطيبات (التكلفة + نسبة):** الزبون يدفع التكاليف المباشرة الفعلية + نسبة إدارة الشركة عليها.
- **الأطراف:** الزبائن، الموردون، الفنيون، الموظفون، المهندسون.
- **المال:** الخزائن والحسابات المصرفية، القبض، الصرف، التحويلات، العُهد، الرواتب والسلف.
- **التشغيل:** المعدات وإيجاراتها، المخزون، البنود العامة ووحدات القياس.
- **المخرجات:** التقارير، العقود المطبوعة، الإيصالات، كشوف الحساب.

يعمل كتطبيق ويب، وكتطبيق سطح مكتب (Windows) مع نسخ احتياطي.

## 3. الوحدات (ما يُعاد بناؤه)

### 3.1 الرئيسية
- لوحة مؤشرات: أرصدة الخزائن، مستحقات الزبائن، ذمم الموردين والفنيين، المشاريع النشطة، تنبيهات (بنود بخطة عمالة ناقصة، عُهد مفتوحة، فواتير غير مسددة).
- لوحة خاصة بالمحاسب.

### 3.2 المشاريع
- قائمة مشاريع المقاولات، وقائمة التشطيبات، وإنشاء/تعديل مشروع (الزبون، النوع، الموقع، التواريخ، الميزانية ونوعها، المهندس المشرف وطريقة الإشراف، نسبة التشطيب، الخزينة الافتراضية).
- **مساحة عمل المشروع** بأقسام: نظرة عامة، المراحل، البنود (المقايسة)، المشتريات، المصروفات، إيجارات المعدات، الإنجاز وأعمال الفنيين، الدفعات، العقود، التقرير، الإعدادات.
- **المراحل:** لكل مشروع مراحل مرقمة برقم مرجعي سنوي، ولكل مرحلة حالة وتواريخ ونسبة اختيارية وخزينة.
- **البنود (المقايسة):** من بند عام أو جديد، بالكمية والسعر وطريقة قياس (طول×عرض×ارتفاع أو معادلة)، ونسبة إنجاز، ومهندس.
- **متطلبات العمالة:** البند العام يحدد التخصصات والأعداد المطلوبة، وتُنسخ لبند المشروع عند إنشائه. تعيين الفنيين على البند، وتنبيه عند نقص الخطة.
- بعد إنشاء المشروع ينتقل المستخدم مباشرة إلى مساحة عمله لإكمال الإعداد.

### 3.3 العقود
- عقود مرتبطة بزبون ومشروع (ومرحلة اختيارياً)، ببنود وشروط، ومكتبة شروط نموذجية، وطباعة بتصميم قابل للتخصيص.

### 3.4 الزبائن
- دليل الزبائن، وكشف حساب لكل زبون **لكل مشروع على حدة**: الالتزام، المقبوض، المتبقي، والرصيد الدائن (الفائض) منفصلاً.
- سجل نشاط الزبائن، وكشف الديون.

### 3.5 الموردون والمشتريات
- دليل الموردين، وفواتير المشتريات بأنواعها: **مواد**، **خدمات مورد**، **مرتجع**. (أعمال الفنيين ليست فاتورة مشتريات، انظر 3.6.)
- السداد: لفاتورة محددة، أو **على الحساب** مع توزيع صريح على الفواتير، أو **مقدم** يبقى ظاهراً كرصيد للمورد حتى يُوزَّع.
- مراجعة واعتماد الفواتير.

### 3.6 الفنيون
- دليل الفنيين مع التخصص (من جدول أنواع الفنيين فقط) وأسعار (يومي، ساعة، متر، قطعة).
- **سجل الإنجاز** هو المصدر الوحيد لمستحق الفني، في المقاولات والتشطيبات معاً.
- الدفعات للفني، والمقدم، والعكس بقيد معاكس. **استلام وديعة من فني** عملية منفصلة باتجاه معاكس.
- كشف حساب الفني: المستحق، المدفوع، المتبقي، والمقدم.

### 3.7 الموظفون والمهندسون
- بيانات الموظفين، مسيرات الرواتب الشهرية، القسائم، السلف واستقطاعها، والعُهد.
- سجل المهندسين وتخصصاتهم وربطهم بحسابات المستخدمين.

### 3.8 الخزائن والمال
- **هيكل الخزائن:** قطاعان رئيسيان (مقاولات، تشطيبات) + خزينة عامة. تحت كل قطاع خزائن نقدية وحسابات مصرفية وفروع. نوع الحساب (نقدي/مصرفي) صفة ثانوية وليس قطاعاً.
- معاملات المشروع لا تستخدم إلا خزائن قطاعه، والقاعدة تفرض ذلك.
- **القبض من الزبائن**، **المصروفات العامة**، **التحويلات بين الخزائن** (حركتان مرتبطتان)، **الديون بين الخزائن**.
- **العُهد:** صرف عهدة لموظف أو مهندس على مشروع، الصرف منها، وتسويتها بإرجاع نقدي أو مصروفات.
- كشف لكل خزينة بكل حركاتها والرصيد بعد كل حركة.

### 3.9 التشغيل
- **المعدات:** السجل، الكميات المتاحة، الحالة، الإيجار للمشاريع (يومي، مع الأضرار)، ومصدر التمويل.
- **المخزون (اختياري، آخر المرحلة د):** المواد، الحركات (وارد/صادر/لمشروع)، حد إعادة الطلب.
- **البنود العامة** و**وحدات القياس** و**أنواع الفنيين**.

### 3.10 التقارير والإدارة
- تقرير المشروع، التقارير المالية العامة، كشف مصروفات كل المشاريع، كشف الإيجارات.
- تصميم الطباعة (ترويسة، شعار، ألوان، خطوط) للعقود والإيصالات والتقارير وقسائم الرواتب.
- المستخدمون، الإعدادات، سجل العمليات، النسخ الاحتياطي والاسترجاع.
- اسم الشركة وبياناتها على كل المطبوعات تُقرأ من الإعدادات فقط (الاسم الافتراضي: **شركة ركاز العقارية**)، ولا يُكتب اسم ثابت في الكود.

### 3.11 محذوفة من v2 (بقرارك)
مراقبة الجودة، سجل المخاطر، الجدول الزمني، أوامر التغيير، التدفق النقدي المتوقع، صفحة الإيراد القديمة، والتقويم. لا تُبنى جداولها ولا صفحاتها.

## 4. القواعد المحاسبية (غير قابلة للتفاوض)

1. **كل عملية مستقلة بمعناها:**
   - قبض الزبون = يخفض دين الزبون + يزيد الخزينة. لا يسدد مورداً ولا فنياً ولا فاتورة.
   - دفعة المورد = تخفض مستحق المورد + تخفض الخزينة.
   - دفعة الفني = تخفض مستحق الفني + تخفض الخزينة.
   - المصروف = يُسجَّل في نطاقه + يخفض الخزينة. مصروف المشروع يدخل تكلفته، والعام لا يدخل أي مشروع.
   - الخزينة هي نقطة الالتقاء الوحيدة بين هذه العمليات.
2. **مصدر واحد لكل حقيقة:**

   | الحقيقة | المصدر الوحيد |
   |---|---|
   | التزام الزبون (مقاولات) | العقود، وإلا مجموع البنود |
   | التزام الزبون (تشطيبات) | التكاليف المباشرة × (1 + النسبة) |
   | ما دفعه الزبون | سندات القبض |
   | الرصيد الدائن للزبون | دفتر الرصيد الدائن (غير قابل للتعديل، العكس بقيد معاكس) |
   | التزام المورد | فواتير المشتريات |
   | ما دُفع للمورد | دفعات المورد وتوزيعاتها (والجزء غير الموزع = مقدم) |
   | مستحق الفني | سجلات الإنجاز |
   | ما دُفع للفني | دفعات الفني |
   | الأثر النقدي | دفتر حركات الخزينة |
   | رصيد الخزينة | **مشتق** من مجموع الحركات، لا يُخزَّن ويُعدَّل يدوياً |

3. **التكلفة المباشرة للمشروع** = مواد + خدمات موردين + مستحقات الفنيين (من الإنجاز) + إيجارات المعدات + مصروفات المشروع. كل تكلفة تُحسب مرة واحدة.
4. **ربحية البند (مقاولات):** القيمة المكتسبة = قيمة البند × نسبة الإنجاز. الربح حتى تاريخه = المكتسب − التكاليف المسندة للبند. لا "ربح متوقع" لبند غير مكتمل.
5. **الاستحقاق منفصل عن النقد:** سداد مورد أو فني لا يغير تكلفة المشروع ولا ربحه.
6. **الفائض لا يُطبَّق تلقائياً:** فائض مشروع لا يسدد مشروعاً آخر إلا بعملية تطبيق رصيد صريحة، لا تتجاوز المتبقي على المشروع الهدف.
7. **دفعات الفني على مستوى الفني،** والمشروع المذكور فيها سياق للعرض فقط ما لم يُوزَّع صراحة.
8. **لا حذف للحركات المالية:** الإلغاء يتم بقيد عكسي مرتبط بالأصل، مع السبب والمستخدم والوقت.

## 5. قواعد التنفيذ التقنية

1. **كل عملية مالية = دالة واحدة في قاعدة البيانات داخل معاملة واحدة.** تكتب السند وحركة الخزينة وأي توزيع معاً أو لا شيء. الواجهة لا تكتب في الجداول المالية مباشرة أبداً.
2. **مفتاح منع التكرار** يُولَّد مرة واحدة عند فتح النموذج ويُعاد استخدامه عند إعادة المحاولة.
3. **أقفال الصفوف** عند حساب المتبقي قبل السداد، لمنع دفعتين متزامنتين على نفس المستحق.
4. **الروابط بالمعرّف فقط:** لا ربط أو حذف بحسب المبلغ أو التاريخ أو الوصف.
5. **الحذف المترابط** للبنود وتعييناتها يتم في دالة واحدة.
6. **أخطاء التحميل لا تظهر كأصفار:** إذا فشل استعلام، تعرض الشاشة خطأً وليس ملخصاً ناقصاً.
7. **الخروج يمسح كل البيانات المخزنة مؤقتاً** في المتصفح.
8. **مخطط قاعدة بيانات واحد نظيف** بترحيلات قليلة مرتبة، وأنواع TypeScript مولدة منه.
9. **اختبارات محاسبية حقيقية** على قاعدة بيانات اختبار معزولة، تفشل فعلاً عند الخطأ، وتعمل مع كل تغيير.

## 7. الواجهات الجديدة (تُبنى من الصفر)

- تصميم جديد بالكامل، عربي من اليمين لليسار، فاتح وداكن، ويعمل على الشاشات الصغيرة.
- **التنقل:** شريط جانبي بستة أقسام (الرئيسية، المشاريع والعقود، أطراف التعامل، المالية، التشغيل، التقارير والإدارة) يظهر لكل دور ما يخصه فقط، ومساحة عمل للمشروع بتبويبات ثابتة، وبحث سريع (Ctrl+K).
- **نمط موحد لكل شاشة:** قائمة بجدول وبحث وفلترة، وصفحة تفاصيل بكشف حساب، ونماذج في لوحة جانبية مع حماية من فقدان المسودة.
- **إضافة سريعة من السياق:** إضافة مورد أو فني أو وحدة قياس من داخل النموذج دون مغادرته.
- كل رقم مالي يعرض مصدره عند الضغط عليه (رابط للحركات التي كوّنته).
- **هيكل الكود:** صفحات صغيرة، ومكونات مشتركة، وطبقة بيانات واحدة تستدعي دوال القاعدة. لا صفحة فوق ~400 سطر.

## 8. التقنيات والمجلد

- **الافتراض:** React + TypeScript + Vite + Tailwind + shadcn/ui، و Supabase (Postgres + Auth + RLS)، و Electron لنسخة سطح المكتب.
- **مشروع Supabase جديد** منفصل عن الحالي، حتى تبقى النسخة الحالية تعمل إلى يوم الانتقال.
- **المجلد:** `E:\ركاز-v2` مستودع git جديد.
- **التسليم على مراحل:** (أ) الأساس والدخول والصلاحيات والتصميم ← (ب) الزبائن والمشاريع والمراحل والبنود والعقود ← (ج) الموردون والفنيون والمصروفات والخزائن والعُهد ← (د) الموظفون والرواتب والمعدات والمخزون ← (هـ) التقارير والطباعة ← (و) سطح المكتب والنسخ الاحتياطي ← (ز) نقل البيانات الحالية بعد مطابقة الأرصدة.

## 9. القرارات المحسومة (15 أكتوبر 2026)

1. الوحدات غير المربوطة (الجودة، المخاطر، الجدول الزمني، أوامر التغيير، التدفق النقدي): **تُحذف.**
2. **المخزون يبقى** كوحدة اختيارية في آخر المرحلة (د). **التقويم يُحذف** (لم يُطلب إبقاؤه).
3. رفع الصور والملفات: **تخزين Supabase، أو Google Drive فقط.** الخدمات الخارجية الأخرى (Cloudinary، ImgBB، FreeImage، PostImages) تُلغى. *الافتراض: Supabase أولاً، وDrive خيار في الإعدادات.*
4. نقل البيانات: لم يُحسم بعد. *الافتراض ما زال: ننقل البيانات الحالية بعد مطابقة الأرصدة.*
5. اسم الشركة: **شركة ركاز العقارية**، ويُقرأ من الإعدادات وليس مكتوباً في الكود. "الفارس الذهبي" خطأ في الوثائق القديمة.

### أثر ذلك على v2
- يؤكد قرار البناء من الصفر بمخطط جديد: لا يُنقل أي ترحيل أو سياسة أو مشغل.

### توصية فورية للنسخة الحالية
ما دامت النسخة الحالية متاحة على الإنترنت، فبياناتها مكشوفة للقراءة والحذف. لم أطبق أي إصلاح لأنه يغير قاعدة تعمل؛ يمكن إغلاق الوصول دون دخول بترحيل واحد إذا طلبت ذلك.
