# تحديث واجهات ركاز

## تنظيم العمل

- يفتح المشروع على المراحل؛ اختيار المرحلة يحدد البنود والمشتريات وأعمال العمال والمصروفات.
- الخلاصة والعقود وإيصالات القبض تخص المشروع بالكامل، ولا تتطلب اختيار مرحلة.
- العناصر القديمة بلا مرحلة لها مدخل مستقل حتى يمكن تنظيمها.
- أزيلت واجهات نسب الإنجاز وأعمدتها المطبوعة. حقول قاعدة البيانات القديمة محفوظة للتوافق، ولا تُستخدم لحساب المؤشرات المعروضة الجديدة.
- «القيمة بعد التكاليف» تعني قيمة المشروع ناقص تكاليفه المسجلة، وليست ربحاً محققاً.

## العمال والمستحقات

داخل البند، زر «العمال» يتيح تعيين عدة عمال، واحداً تلو الآخر. يتيح خيار تسجيل المستحق إدخال الكمية والسعر وترحيل المبلغ بواسطة العملية المحاسبية القائمة، مع ربطه بالمشروع والمرحلة والبند. التعيين والتسجيل طلبان منفصلان؛ عند نجاح التعيين وفشل التسجيل تظهر رسالة واضحة وزر إعادة المحاولة بالمفتاح نفسه. نسخ التعيينات بين البنود ينسخ خطة العمالة فقط، ولا ينسخ قيوداً مالية.

## الاتجاه البصري

قائمة جانبية فاتحة، أرضية محايدة، أسطح واضحة، لمسات بنية وذهبية، حقول أكبر، وإجراءات ظاهرة في الجداول. النظام يحتفظ بالخطوط العربية واتجاه اليمين إلى اليسار والوضع الداكن وتقليل الحركة.

مراجع البحث:
- [Linear Projects](https://linear.app/docs/projects): تنظيم مساحة المشروع وتفاصيلها والتنقل السياقي.
- [Attio](https://attio.com/): مرجع لواجهات إدارة البيانات.
- [Impeccable](https://github.com/pbakaus/impeccable): مهارة مقترحة لتدقيق التصميم وصقله؛ لم تُثبت ضمن هذا التحديث.

## التحقق

`tests/project-workflow.cjs` يختبر تدفق المراحل، عزل بنود المرحلة، تعيين عاملين، تسجيل المستحقات المرتبطة بالبند، إعادة المحاولة، الكتابة في صرف الدفعات، العقود المستقلة عن المراحل، وإلغاء نسب الإنجاز. يعترض الاختبار كل اتصالات قاعدة البيانات ببيانات تجريبية ولا يكتب في الحسابات الفعلية.

تشغيله يتطلب خادم التطوير على المنفذ 5173 وPlaywright ومتصفح Edge. يمكن تحديد مسار Playwright عبر `PLAYWRIGHT_PATH`.
